The trick that works on any site

Save the page. Ask AI. Get a script.


// paste straight into the DevTools console
document.querySelectorAll('.vt-row')
  .forEach(r => r.style.outline = '2px solid #0099CC');
The reusable method
  • Capture: save the page as HTML or a web archive.
  • Ask: feed the DOM to ChatGPT or Claude.
  • Test: run the script locally before the real site.
  • Package: turn the useful bit into something repeatable.
Timing: 2 minutes. Live-along three: right click, save the page, paste a line into the console, watch the page change in front of the room. This is the heart of the talk. You are not asking the model to operate the system. You are asking it to help you reshape a page you already have. On a past project this exact move was how we did A and B testing, which is billable consultancy work, not a toy.

Make it stick

A script earns its keep when it comes back tomorrow.

Install A userscript manager

Tampermonkey, Violentmonkey, or Greasemonkey. They handle install, update, and the GM_* superpowers normal page code lacks.

Share Extension shaped

A console trick helps me. A packaged extension helps the colleague who just wants it to work.

Timing: 2 minutes. A userscript is JavaScript that runs on matching pages. A manager makes it repeatable. The honest gap: a console script is great for me and useless for my non technical colleague, who is not going to paste anything into anything. That gap is the reason the next rung exists.

Solve the general problem

I built a compiler, not a single extension.

The question What is the generic version?

Do not package one Vertec script. Build a tool that turns any userscript into a real extension.

UserScript-Compiler One script, three browsers

Polyfills GM_* methods, writes the manifest, outputs Chrome, Firefox, and Safari packages, plus a submission guide.

Timing: 2 minutes. This is the forward deployed instinct in miniature: turn a one off fix into reusable leverage. "One fix" becomes "a tool that makes fixes". Keep taste central

If the line sounds like LinkedIn with a fever, cut it. The agent is fast, not tasteful.

Fast is useful. Taste is still manual.

Essential AI literacy

Spot the AI slop.

The tells: "it's not X, it's Y", em dashes everywhere, ASCII arrows, neat lists of three, cards and gradient fog (Codex's signature look), image defects, and, at Zühlke, an umlaut someone clearly typed by hand. Output is raw material. Make it yours before it makes you look haunted.

Timing: 2 minutes. Teach this as a skill, because the real skill is judgement. Text tells: negative parallelism, em dash overkill, the rule of three, words like delve and seamless, confident paragraphs nobody asked for. Code tells: emojis in comments, step by step comment patterns, bloat. Be fair, an em dash alone proves nothing. Link it back to CDM: the loop only works if humans inspect the artefacts and improve them.

Know when to stop

Better is not always more AI.

Where rough output is fine

Throwaway personal helpers and one off exploration. Vibe coding raises the floor.

Where it never is

Client work, billing, HR, anything a teammate maintains. Agentic engineering preserves the ceiling.

Beware the AI vampire

The trap is opportunity cost, not token cost. The limit that matters resets at sunrise, not midnight.

A multi-agent swarm to fill three timesheet rows is a microservice for a to-do list. Sometimes the answer is a one line script.

Timing: 2 minutes. Karpathy's framing: vibe coding raises the floor, agentic engineering preserves the ceiling. Decide by the blast radius. The AI vampire is the person who stays up because the usage limit resets at midnight, and pays for it with the far more expensive resource, their evening. Faster, clearer, or cheaper by hand? Do it by hand.
