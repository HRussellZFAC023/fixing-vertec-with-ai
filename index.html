Field note

The enemy is not time recording.

The enemy is making the human act as the integration layer.

The bill still has to be right. The approval still has to be fair. The human should not have to become a very tired API gateway every Friday.

Before the build

Do the anthropology.

Watch the task. Name the workarounds. Ask what the tool is forcing people to remember. Then decide whether AI should critique, assist, test, or stay out of the way.

This replaces the too-literal "play around first" idea. The workshop begins with noticing: what is the real job, what is policy, what is tool friction, and what is just ceremony?

Trade-offs

No single approach wins forever.

ChatGPT critique

Best for finding words, structure, and first requirements. Weak at proving behaviour.

Userscript

Best for quick humane relief. Brittle if the DOM shifts.

Harness + tests

Best for reproducibility. Requires discipline before the demo feels exciting.

Direct API

Best for robust workflows. Needs permission, observability, and policy clarity.

MCP + automation

Best for chat-native work. Needs confirmations and a clean audit trail.

The superapp question

Is Codex signed into everything the future?

Maybe. But the useful version is not "the AI does whatever it wants". It is a trusted workbench with tools, memory, browser context, Git history, approvals, and boring evidence.

Subagents

Manage the swarm. Do not become the swarm.

Give each agent a bounded lane: research, fixture, v1, tests, docs, API investigation. Keep integration, risk calls, and taste with the human lead.

Takeaway

Make the work visible. Then make the improvement boring.

The best AI demo is not the one that looks most autonomous. It is the one a sceptical teammate can inspect, run, question, and safely adapt.
